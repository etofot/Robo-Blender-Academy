## 2. Общий скилл: распределение плотности деталей

### Разбить робота на функциональные зоны

Предлагаемый художественно-технический пресет:

| Зона | Характер детализации | Что размещать |
|---|---|---|
| Крупная внешняя броня | Низкая плотность | Редкие люки, швы, крепёж, маркировка |
| Плечевые и тазовые узлы | Высокая плотность | Приводы, оси, ограничители, шланги, разъёмы |
| Колени и локти | Средняя/высокая | Поршни, направляющие, защитные кожухи |
| Двигательный отсек | Высокая | Трубопроводы, решётки, сервисные блоки |
| Кабина | Контролируемая | Рамки, уплотнения, замки, датчики |
| Ступни | Средняя | Шарниры, крепления, контактные накладки |

Начальная рекомендация — оставлять большую часть крупных бронепанелей чистой. Это художественный ориентир, не физическая норма: плотность должна подчиняться читаемости силуэта и масштабу изображения.

### Перед спавном создать исключения

Каждая зона получает маски:

```text
detail_allowed
mounting_surface
joint_swept_volume
service_access
optics_keepout
exhaust_keepout
decal_allowed
wear_exposure
```

Особенно важен `joint_swept_volume`: область, которую занимает механизм при движении. Нельзя заполнять её гриблями даже тогда, когда в текущей позе там визуально пусто.

### Порядок детализации

```text
Приводы и реальные соединения
    ↓
Сервисные узлы и крепёж
    ↓
Панели и люки
    ↓
Кабели и шланги
    ↓
Вторичные грибли
    ↓
Декали, сколы, загрязнения
```

Случайность разрешается внутри назначенных областей, но не определяет механическую схему.

## 3. KIT OPS 2 PRO + MASTER-MEGA300TECH V5

Источники: [описание KIT OPS 2](https://www.chippwalters.org/kit-ops) · [историческая документация](https://www.filedn.com/lLMW4jXsJqxXkRYjd1UCoKL/online_docs/kitops.html).

### Что подтверждено

KIT OPS использует INSERT-ассеты на основе Blender-файлов: они могут добавлять объекты, выполнять вырезы или существовать как самостоятельные детали. Историческое описание KIT OPS 2 указывает Blender 2.83+, но это не подтверждает совместимость старой сборки с Blender 5.x. [chippwalters](https://www.chippwalters.org/kit-ops)

Состав именно MASTER-MEGA300TECH V5 в надёжном источнике подтвердить не удалось. Поэтому пакет не предполагает, что все элементы библиотеки являются готовыми механическими деталями: часть может быть cutters.

### Программный интерфейс

Контракт собственной обёртки:

```python
insert_kit(
    asset_path,
    root_id,
    mount_matrix,
    target_id,
    boolean_mode,
    options,
)
```

Это не сигнатура KIT OPS.

Стандартный Blender API позволяет загрузить объекты из `.blend`:

```python
with bpy.data.libraries.load(asset_path, link=False) as (src, dst):
    dst.objects = [
        name for name in src.objects
        if name in requested_objects
    ]

loaded = [obj for obj in dst.objects if obj is not None]

for obj in loaded:
    target_collection.objects.link(obj)
```

Однако импорт datablocks не равен штатной обработке INSERT. Собственный адаптер обязан сохранить parenting, внутренние ссылки, модификаторы и правильно назначить целевые объекты.

### Скилл детализации

1. Проиндексировать библиотеку.
2. Для каждого ассета определить:
   - `role`: cutter / additive / assembly;
   - размеры и локальные оси;
   - root;
   - точки крепления;
   - внутренние зависимости;
   - требования к boolean.
3. Импортировать прототип в тестовую коллекцию.
4. Привести к согласованным единицам.
5. Разместить через монтажную матрицу.
6. Применять boolean только к cutter-элементам.
7. Проверять доступ к соседнему крепежу и механизмам.

### Важный хак

Не назначать всем деталям полную копию меша.

- Идентичные болты и муфты — общий mesh datablock или инстансы.
- Уникальный вырез или индивидуальная правка — отдельная копия.
- Сборка из нескольких объектов — сохранённая иерархия.

Но нельзя слепо копировать boolean-модификаторы: их ссылки могут продолжать указывать на объекты исходного прототипа.

## 5. Cablerator v1.6.0

Источники: [руководство](https://cablerator.readthedocs.io/) · [release log](https://cablerator.readthedocs.io/en/latest/notes/index.html).

### Что использовать

Cablerator поддерживает создание из рёбер и объектов, профили, сегменты, коннекторы, hooks и работу с несколькими кривыми. В 1.6.0 добавлена переработка плотных кривых в Bézier-кривые с меньшим числом точек. Asset Browser-интеграция для профилей, сегментов и коннекторов существует с 1.4.5. [cablerator.readthedocs](https://cablerator.readthedocs.io/)

### Программный интерфейс

Предлагаемый контракт:

```python
route_harness(
    port_a,
    port_b,
    tangents,
    guides,
    profile_id,
    connector_ids,
    slack,
    options,
)
```

Порт должен содержать не только позицию:

```python
port = {
    "position": (x, y, z),
    "outward_axis": (nx, ny, nz),
    "radius": 0.008,

    "owner_bone": "forearm",

```

Публичный стабильный scripting API Cablerator 1.6.0 не подтверждён; в документации создание кабеля описано как modal-workflow. [cablerator.readthedocs](https://cablerator.readthedocs.io/)

### Скилл жгута

1. Получить позиции и направления портов A и B.
2. Создать пространственные маршруты.
3. Задать касательные концов.
4. Добавить необходимую слабину.
5. Проверить радиус изгиба.
6. Назначить профили и сегменты.
7. Ориентировать муфты по касательным маршрута.
8. Добавить привязки к движущимся узлам.
9. Проверить крайние положения суставов.

### Контроль Bézier-касательных

Для двухточечной кривой:

\[
H_{A,\text{right}}=A+h_A t_A,
\]

\[
H_{B,\text{left}}=B+h_B t_B,
\]

где \(t_A\) и \(t_B\) направлены от соответствующих портов в свободное пространство.

Это позволяет задать выход кабеля из муфт без случайного излома. Скрипт в архиве использует явные handles, а не AUTO.

### Хаки

- Сначала строить маршруты, потом коннекторы.
- Проверять, что ось ассета муфты соответствует оси, принятой адаптером.
- Для гофры ограничивать плотность сегментов.
- Hooks не гарантируют сохранение длины и отсутствие самопересечений при анимации.
- Кабель, красиво выглядящий в rest pose, ещё не прошёл механическую приёмку.

## 9. Pointiness, AO и Curvature: как использовать правильно

### Pointiness

Geometry → Pointiness — приближение кривизны по вершинам, доступное в Cycles. Светлые значения соответствуют выпуклым областям, тёмные — вогнутым. Это не универсальная физическая карта износа. [docs.blender](https://docs.blender.org/manual/en/latest/render/shader_nodes/input/geometry.html)

Предлагаемая маска:

\[
M_{\text{wear}}
=
M_{\text{convex}}
\cdot M_{\text{breakup}}
\cdot M_{\text{exposure}}
\cdot M_{\text{artist}}.
\]

То есть:

- кандидат на выпуклую кромку;
- неоднородность;
- доступность внешнему контакту;
- художественные ограничения.

Не стоит одинаково стирать краску со всех рёбер, включая закрытые внутренние соединения.

### Ambient Occlusion

AO определяет затенённость полусферы над поверхностью, а не наличие масла. AO Node имеет Distance, Inside и Only Local; в Cycles он может быть дорогим, поэтому документация рекомендует запекание, когда важна производительность. [docs.blender](https://docs.blender.org/manual/en/latest/render/shader_nodes/input/ao.html)

Для масла:

\[
M_{\text{oil}}
=
M_{\text{cavity}}
\cdot M_{\text{leak source}}
\cdot M_{\text{flow path}}.
\]

Нужен источник: разъём, сальник, сервисная пробка. Направление потёка задаётся отдельно.

### Как запекать

В стандартном baking Blender есть AO и Emit, но нет универсального отдельного прохода `POINTINESS` или `CURVATURE`. Произвольную скалярную маску можно подключить к Emission и запечь как Emit. [docs.blender](https://docs.blender.org/manual/en/latest/render/cycles/baking.html)

```python
bpy.ops.object.bake(type="AO")
```

Либо для подготовленной маски:

```python
# Маска -> Emission -> Material Output
bpy.ops.object.bake(type="EMIT")
```

Обязательные условия:

- mesh с UV;
- активный Image Texture target в каждом материале;
- Cycles;
- корректные UV без нежелательных наложений;
- padding вокруг островов;
- явное сохранение результата. [docs.blender](https://docs.blender.org/manual/en/latest/render/cycles/baking.html)

Для управляемого AO с конкретным Distance используйте AO Node → Emission → Emit. Не считайте стандартный AO bake тождественным любым настройкам AO-узла.

## 10. Готовый скрипт жгута с муфтами

В архиве находится `cable_bundle.py`. После выполнения его содержимого внутри Blender:

```python
result = build_bundle(
    A=(0.0, 0.0, 0.0),
    B=(0.0, 0.0, 0.8),
    count=5,

    A_axis=(0.0, 0.0, 1.0),
    B_axis=(0.0, 0.0, -1.0),

    frame_normal=(1.0, 0.0, 0.0),

    hose_radius=0.008,
    bundle_radius=0.035,
    seed=7,
)
```

### Что он создаёт

При `count=5`:

- 5 Bézier-шлангов;
- 20 mesh-элементов муфт: воротник и шестигранная часть на каждом конце каждого шланга;
- отдельную коллекцию;
- резиновый материал шлангов;
- материал окрашенного титана с маской потертостей на муфтах.

Материал использует Pointiness и noise, поэтому live-вариант рассчитан на Cycles. Для Eevee или игрового движка нужно запечь маски. [docs.blender](https://docs.blender.org/manual/en/latest/render/shader_nodes/input/geometry.html)

### Что возвращает

    "objects": 25,

    "backend": "native_reference",

`addon_calls` намеренно пуст: этот скрипт не выдаёт стандартное построение кривых за вызов Cablerator.

### Запекание маски износа

После подготовки UV на металлическом mesh-объекте:

```python
image = bake_scalar_mask(
    obj=metal_connector,
    node_name="WEAR_MASK",
    size=1024,
)
```

Функция:

- проверяет mesh, UV и материалы;
- работает с временными копиями материалов;
- подключает выбранную маску к Emission;
- выполняет Emit bake;
- восстанавливает материалы и основные изменённые настройки;
- возвращает Image datablock.

Изображение нужно отдельно сохранить. У резинового материала узла `WEAR_MASK` нет — это намеренное разделение материалов.

### Ограничения шаблона

- Жгут статичен: движение суставов не обновляет его автоматически.
- Нет проверки столкновений маршрутов.
- Нет расчёта минимального радиуса изгиба.
- Муфты — визуальные заготовки без резьбы и внутренних каналов.
- UV генератор не создаёт.
- Каждый запуск создаёт новую коллекцию.
- Это шаблон для тестирования в Blender, а не уже прошедший production-приёмку инструмент.

## 11. Задача агенту на внедрение блока 3

```text
1. Выполнить discovery установленных аддонов.
2. Зафиксировать версии Blender, аддонов и реальные operator IDs.
3. Проиндексировать KPACK и отделить cutters от additive assets.
4. Создать семантические зоны детализации и no-detail masks.
5. Подключить KIT OPS для сервисных деталей.
6. Подключить Random Flow для ограниченной вторичной детализации.
7. Подключить Cablerator для маршрутов и коннекторов.
8. Создать отдельные материалы металла, краски, резины и масла.

10. Выполнить collision/pose/UV/bake QA.

```

Критерий успеха — не «добавлено 500 объектов», а механически читаемая сборка: сохраняется силуэт, суставы двигаются, кабели имеют понятные подключения, крупная броня не забита шумом, а материалы и детализация укладываются в игровой бюджет.
