## 2. Общий пайплайн кабины по двум проекциям

### Система координат

Для кабины шагохода предлагаю фиксировать:

- X — от носа к корме.
- Y — поперечная координата.
- Z — высота.
- Начало координат — конструктивная точка, например передняя монтажная плоскость, а не автоматически меняющийся центр bounding box.

Из верхней проекции агент извлекает полуширину \(w(x)\), из боковой — верхнюю и нижнюю границы \(z_t(x)\), \(z_b(x)\).

Станция задаётся:

\[
S_i=\left(x_i,w_i,z_{b,i},z_{t,i}\right).
\]

Две проекции не задают единственную поверхность. Поэтому агент должен дополнительно выбрать тип поперечного профиля: фасеточный, эллиптический, скруглённо-прямоугольный или смешанный. Это проектное предположение нужно записывать в спецификацию детали, а не скрывать.

### Как получить единую поверхность без трещин

Предлагаемый контракт:

1. У всех станций одинаковое число точек.
2. Одинаковое направление обхода.
3. Одинаковый индекс начала обхода — например нижняя правая конструктивная кромка.
4. Явный порядок станций по X.
5. Между соседними станциями строятся грани с общими индексами вершин.
6. Торцы закрываются отдельно.
7. Проверяются открытые границы и связность.

Операция Join независимых объектов сама по себе не создаёт общую топологию. А общие вершины не гарантируют гладкие блики: отсутствие трещин и качество сопряжения — разные критерии.

Для программного создания контрольных кривых у Blender документированы `Spline.use_cyclic_u`, координаты и handles Bézier-точек, их `tilt` и `radius`. Это надёжный интерфейс подготовки входных данных для аддонов. [docs.blender](https://docs.blender.org/api/current/bpy.types.BezierSplinePoint.html)

## 3. Bezier Mesh Shaper v0.9.67

Источник: [документация автора](https://superhivemarket.com/products/bezier-mesh-shaper/docs).

### Роль в роботостроении

Не создавать кабину с нуля, а корректировать её продольные кромки и локальные переходы:

- силуэт крыши;
- линию скул;
- переход носа в основную капсулу;
- обтекатель плечевого механизма;
- мягкий переход между двумя заранее построенными объёмами.

Документированный workflow: выделенная открытая цепочка вершин либо несколько вершин, между которыми находится кратчайший путь; затем управление появившейся кривой. Замкнутую выделенную цепочку автор не рекомендует для этого сценария. [superhivemarket](https://superhivemarket.com/products/bezier-mesh-shaper/docs)

### Python/bpy-сигнатуры

Публичную сигнатуру безмышечного вызова именно v0.9.67 я не подтвердил. В пакете используется собственный контракт:

```python
shaper_deform(
    mesh,
    vertex_chain,
    target_curve,
    influence_weights,
    options,
)
```

Это функция будущего адаптера, не название API производителя.

Подготовка целевой кривой через стандартный API:

```python
curve = bpy.data.curves.new("RoofGuide", "CURVE")
curve.dimensions = "3D"

spline = curve.splines.new("BEZIER")
spline.bezier_points.add(len(points) - 1)

for bp, co in zip(spline.bezier_points, points):
    bp.co = co
    bp.handle_left_type = "ALIGNED"
    bp.handle_right_type = "ALIGNED"
    bp.tilt = 0.0
    bp.radius = 1.0
```

Важно: `ALIGNED` задаёт тип handles, но сам по себе не вычисляет нужные проектные касательные. Положения handles агент должен задать либо получить из отдельной процедуры аппроксимации. Поля точек и допустимые типы handles документированы Blender. [docs.blender](https://docs.blender.org/api/current/bpy.types.BezierSplinePoint.html)

### Пайплайн каплевидной кабины

1. Построить первоначальный loft по станциям.
2. Найти продольную цепочку верхней кромки.
3. Создать направляющую по боковому чертежу.
4. Исключить из деформации монтажные площадки и границу остекления.
5. Выполнить деформацию через проверенный адаптер.
6. Повторно сравнить вид сверху: коррекция одного силуэта не должна испортить другой.
7. Проверить зазоры с плечевыми узлами.

### Параметры, которые нужно раскрыть агенту

- `Use Direction` — учитывает ориентацию кривой при деформации.
- `Use Extremes` — влияние крайних контрольных точек.
- Falloff: Off / Distance / Connected.
- `Force Primary Vertices` — полное влияние на первичные вершины.
- Unbind Curve — изменение управляющей кривой без немедленной деформации меша. [superhivemarket](https://superhivemarket.com/products/bezier-mesh-shaper/docs)

Имена этих настроек в документации не означают, что так же называются Python-свойства вашей сборки.

## 4. Navid3ds Interactive Loft Pro

Источники: [репозиторий](https://github.com/navid3ds/Navid3ds-Interactive-Loft-Pro) · [описание расширения](https://iblender.org/add-ons/navid3ds-interactive-loft-pro/).

### Роль

Основной кандидат блока для построения оболочки между сечениями. В описании проекта заявлены интерактивный loft, изменение порядка кривых, управление формой, разрешением и интерполяцией, а также mesh baking. [github](https://github.com/navid3ds/Navid3ds-Interactive-Loft-Pro)

### Python/bpy-сигнатуры

Репозиторий найден, но исходный `__init__.py` через доступный инструмент не удалось прочитать. Поэтому точные операторы не подтверждены.

Контракт адаптера:

```python
loft_profiles(
    profiles,
    ordered_ids,
    sample_count,
    caps,
    options,
)
```

Что агент должен проверить в локальных исходниках:

- используется ли порядок выделения или собственный список;
- как выполняется ресэмплинг кривых;
- как выбирается seam;
- как задаётся интерполяция;
- каким способом обновляется live mesh;
- что делает bake и прекращает ли он последующее обновление.

### Пайплайн клиновидной кабины

1. Создать носовую станцию с ненулевой шириной.
2. Добавить станции основания лобового стекла и верхней границы стекла.
3. Добавить станцию максимальной ширины.
4. Добавить заднюю монтажную станцию.
5. Согласовать вершины верхних фасок между станциями.
6. Построить loft с явным порядком.
7. Проверить торцы, seam и диагональное перекручивание.
8. Запечь отдельную рабочую копию.

Не сводить все точки носовой станции в одну позицию: это создаёт вырожденные грани. Острый нос нужно оформлять отдельным корректным завершением поверхности.

### Математика формы

Между соседними сечениями при линейном loft:

\[
P(u,v)=(1-u)C_i(v)+uC_{i+1}(v).
\]

Здесь \(v\) должен обозначать соответствующую конструктивную позицию на обоих сечениях. Если на одном профиле это крыша, а на другом — боковина, loft перекрутится независимо от качества аддона.

Для скруглённого корпуса можно применять более плавную интерполяцию, но после неё проверять overshoot: поверхность не должна выходить за заданные габариты.

## 6. Bend Face

Источник: [описание и инструкция](https://superhivemarket.com/products/bend-face).

### Роль

Локальные жёсткие повороты и rotate-extrude:

- наклон стекольной рамки;
- загиб монтажного язычка;
- поворот панели вокруг петли;
- создание изогнутого патрубка последовательностью сечений.

Аддон документирует вращение/перемещение относительно ребра либо нормали грани, числовой угол/расстояние и Rotate Extrude с числом копий. [superhivemarket](https://superhivemarket.com/products/bend-face)

### Python/bpy-сигнатуры

Документация описывает интерактивный выбор оси мышью, но не подтверждённый безмышечный оператор с координатами pivot.

Контракт:

```python
rotate_faces(
    mesh,
    face_ids,
    pivot,
    axis,
    angle_rad,
    options,
)
```

При привязке нужно проверить единицы: UI может показывать градусы, а Python-свойство — хранить радианы.

### Математика пивота

\[
p'=c+R_{\mathbf a}(\theta)(p-c).
\]

- \(c\) — точка на оси.
- \(\mathbf a\) — нормализованное направление оси.
- \(\theta\) — угол.

В архиве есть реализация:

```python
rotate_about_axis(point, pivot, axis, angle_rad)
```

Проверки:

- точка на оси остаётся неподвижной;
- расстояние до оси сохраняется;
- неподвижная сторона шарнира не деформируется;
- перемещение не зависит от текущего 3D Cursor.

### Для кабины

Скошенное стекло лучше сначала определить конструктивными плоскостями и станциями, а Bend Face применять для локальной рамки или откидной панели. Поворот произвольной части уже готового монокока легко нарушает согласование соседних поверхностей.

### Python/bpy-сигнатуры

Контракт адаптера:

```python

    mesh,
    vertex_ids,
    frame,
    neutral_radius,
    arc_length,
    options,

```

Нельзя считать, что внутренний параметр аддона принимает радиус: документация говорит об угле изгиба. Преобразование радиуса в параметры нужно проверить локально.

### Математика радиуса

Для длины нейтральной линии \(L\):

\[
\theta=\frac{L}{R}.
\]

Для собственного референсного изгиба в плоскости XZ:

\[
\phi=\frac{x}{R},
\]

\[
x'=(R+z)\sin\phi,
\qquad
z'=(R+z)\cos\phi-R,
\qquad
y'=y.
\]

Это формула ядра в архиве, а не утверждение об алгоритме Simple Bend EX.

Для толщины \(t\):

\[
R_{\text{inner}}=R-\frac{t}{2},
\qquad
R_{\text{outer}}=R+\frac{t}{2}.
\]

Радиус корпуса и радиус нейтральной линии — разные величины. Если кожух должен проходить над суставом, рассчитывать зазор нужно по внутренней поверхности кожуха.

### Контроль плотности

Для аппроксимации дуги хордовая ошибка:

\[
e=R\left(1-\cos\frac{\Delta\theta}{2}\right).
\]

Отсюда можно определить требуемое число сегментов под заданный допуск, вместо постоянного «добавить 64 subdivisions».

Но это только контроль аппроксимации дуги. Он не доказывает отсутствие глобальных пересечений.

## 9. Как сохранять механические зазоры

### Не заменять offset масштабированием

Равномерное масштабирование контура не создаёт равномерного расстояния до исходного контура.

Для общей поверхности нужен offset по нормали:

\[
S_d(u,v)=S(u,v)+d\,n(u,v).
\]

Даже корректный offset способен самопересекаться: локально при чрезмерной величине относительно радиуса кривизны и глобально между удалёнными участками поверхности. [sciencedirect](https://www.sciencedirect.com/science/article/abs/pii/S0010448599000135)

Поэтому для робота:

- цилиндрические посадки рассчитывать радиусами;
- плоские сопряжения — расстояниями между плоскостями;
- сложные оболочки — offset плюс отдельная проверка пересечений;
- уплотнитель вокруг окна — отдельный профиль и отдельно заданный зазор.

### Проверять диапазон движения

Зазор в одной позе не гарантирует зазор при движении.

Предлагаемый критерий:

\[
g_{\min}=\min_{q\in Q} d\big(A(q),B(q)\big),
\]

где \(Q\) — допустимые положения механизма.

В пакет включено требование проверять закрытое, промежуточные и крайние положения. Такая выборка — дискретный тест, а не математическая гарантия на всём непрерывном диапазоне.

## 10. Что делает код из архива

После выполнения `robot_forms.py` через MCP:

```python
result = build_reference_cockpit()
```

Он создаёт:

- семь упорядоченных контрольных станций;
- единый замкнутый наружный объём кабины;
- фасеточную каплевидно-клиновидную форму;
- наклонную переднюю зону, обозначенную материалом остекления;
- два боковых boolean-паза;
- базовый QA: границы, non-manifold рёбра, вырожденные грани, объём.

Ограничения примера:

- Это нативный референсный backend, не вызов перечисленных аддонов.
- Остекление — материал на гранях, не отдельная стеклянная вставка.
- Корпус — внешний объём, не рассчитанная полая силовая оболочка.
- Нет проверки самопересечений и минимальных зазоров.
- Runtime в Blender ещё не проверен.

Пакет полезен как эталон входных данных и результата для сравнения аддонных адаптеров. Не следует засчитывать успешный запуск этого генератора как успешную интеграцию Navid Loft или Bezier Mesh Shaper.

## 11. Правильная последовательность внедрения

1. Запустить `discover_block2.py` и получить реальные операторы установленных сборок.
2. Первым подключить Navid Loft: станции → поверхность.
3. Затем GridModeler / Face Cutter / Round Inset: локальные конструктивные элементы.
4. Подключить Bezier Mesh Shaper только для управляемой коррекции формы.
5. Подключить Bend Face и Simple Bend EX для рамок, патрубков и кожухов, а не для бесконтрольного изгиба всей кабины.
6. Последним CurveBasher: кабели, уплотнители и сегментированные элементы.

Для каждого адаптера в пакете задано правило: неизвестная привязка возвращает `BINDING_REQUIRED`; нативная операция не подменяет аддон молча. Это позволит агентам накапливать действительно проверенные скиллы, а не коллекцию правдоподобных, но неработающих `bpy.ops`.
