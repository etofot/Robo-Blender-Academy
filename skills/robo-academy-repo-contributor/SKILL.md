## 2. Пошаговый алгоритм работы агента

### Шаг 1: Клонирование или синхронизация репозитория
Перед внесением изменений всегда получи свежее состояние репозитория:

```bash
# Клонирование (если папки еще нет):
git clone https://etofot:$GITHUB_PAT@github.com/etofot/Robo-Blender-Academy.git
cd Robo-Blender-Academy

# Настройка локального пользователя для коммитов:
git config user.name "etofot"
git config user.email "lovecyberboy@gmail.com"

# Если репозиторий уже склонирован — подтяни изменения:
git pull origin main
```

### Шаг 2: Правила размещения новых файлов (Каталогизация)
Каждый новый файл обязан помещаться строго в предназначенный для него каталог:

| Тип контента | Куда сохранять | Примеры файлов |
| :--- | :--- | :--- |
| **Интерактивная студия и веб-код** | `dreadnought-3d-ik-studio/` | Обновления `index.html`, новые шейдеры щита, UI-кнопки |
| **Уроки и документация школы** | `robo_blender_academy/<модуль>/` | Markdown-гайды по хард-сурфейсу, риггингу, анимации |
| **Автономные навыки для ИИ** | `skills/<имя-скилла>/` | Файлы `SKILL.md` и вспомогательные скрипты генерации |
| **Процедурные Python-скрипты Blender** | `scripts/` | `build_new_mech.py`, скрипты сборки деталей, тесты |
| **Новые 3D-модели и исследования ног/узлов** | `LEG_STUDY_LAB/` или `assets/` | `.blend` сцены (без autosave-мусора), `.glb`, рендеры верификации |
| **Аддоны Blender** | `blender_addons/` | Проверенные процедурные аддоны (размером до 45 МБ) |

### Шаг 3: Контроль качества перед коммитом (Pre-Flight Checks)
1. **Контроль размера файлов (Критично!):**
   * GitHub отклоняет файлы размером $> 100\text{ МБ}$ и выдаёт предупреждение при $> 50\text{ МБ}$.
   * Убедись, что ни один файл не превышает $45\text{ МБ}$.
   * Запрещено коммитить архивы `.rar` / `.7z` размером $100+\text{ МБ}$.
2. **Исключение мусорных файлов:**
   * В репозиторий НЕ должны попадать: автосохранения Blender (`*.blend1`, `*.blend2`), кэш Python (`__pycache__/`, `*.pyc`), виртуальные окружения (`.venv/`) и `node_modules/`.
   * **Секреты и токены:** Ни в коем случае не записывать открытые токены (`ghp_...`) в код файлов репозитория — GitHub Push Protection автоматически блокирует такие коммиты. Токен передается только через переменную окружения `GITHUB_PAT`.
3. **Обновление README.md:**
   * Если добавлен новый робот, скрипт или модуль школы — добавь краткое описание и ссылку в корневой `README.md`.

### Шаг 4: Фиксация и отправка изменений (Commit & Push)

```bash
# 1. Проверь статус измененных файлов
git status

# 2. Добавь файлы в индекс
git add .

# 3. Сделай осмысленный коммит
git commit -m "feat(mech): добавлена процедурная генерация корпуса нового шагателя"

# 4. Отправь в ветку main
git push origin main
```
