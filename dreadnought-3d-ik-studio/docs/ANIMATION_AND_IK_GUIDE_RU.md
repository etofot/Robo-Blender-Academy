# Руководство и Скилл-Инструкция для ИИ-Агентов: Создание Процедурных 3D-Мехов, Развертки и IK-Анимаций (`procedural-3d-mech-animator`)

Этот документ служит одновременно **технической документацией к проекту `Dreadnought MK-IV TITAN`** и **готовым скиллом-инструкцией (`SKILL.md`) для других ИИ-агентов**, чтобы любой агент мог с нуля воспроизвести подобного 3D-робота, создать топологическую развертку по изгибам брони и запрограммировать реалистичные физические анимации с инверсной кинематикой (Zero-Drift Foot IK).

## 1. Архитектура 3D-модели и Топологическая UV-развертка (Conformal Topology UVs)

### Почему обычные текстуры выглядят как «спортивный костюм» и как это исправить
Если накладывать текстуру на 3D-модель через простую плоскую проекцию в мировых координатах (`u = worldX`, `v = worldY`), рисунок швов и заклепок режет грани под случайными углами и не следует за наклонами бронеплит.

Чтобы рисунок **повторял все изгибы, сужения и фаски каждой детали**, развертка должна быть **параметрической (конформной)** и генерироваться прямо внутри функции построения геометрии `buildLoftGeometry(slices, capBot, capTop)`:

* Координата **`U` (`0.0 .. 1.0`)** бежит непрерывно по периметру поперечного сечения детали (`i / nPts`).
* Координата **`V` (`0.0 .. 1.0`)** идет снизу вверх вдоль колец сечений детали (`r / (numRings - 1)`), от нижней фаски к верхней.
* Для каждого восьмигранного скошенного блока (`nPts = 8`) углы граней всегда попадают ровно на `U = 0.0, 0.25, 0.50, 0.75`, а нижняя и верхняя фаски — на `V = 0.00..0.10` и `V = 0.90..1.00`.

```javascript
// Конформная генерация треугольников и UV-координат по сечениям (slices)
for (let r = 0; r < numRings - 1; r++) {
  const v0 = r / (numRings - 1);
  const v1 = (r + 1) / (numRings - 1);
  for (let i = 0; i < nPts; i++) {
    const u0 = i / nPts;
    const u1 = (i + 1) / nPts;

    const p00 = slices[r][i];
    const p10 = slices[r][(i + 1) % nPts];
    const p01 = slices[r + 1][i];
    const p11 = slices[r + 1][(i + 1) % nPts];

    positions.push(...p00, ...p10, ...p11);
    uvs.push(u0, v0, u1, v0, u1, v1);

    positions.push(...p00, ...p11, ...p01);
    uvs.push(u0, v0, u1, v1, u0, v1);
  }
}
```

## 2. Внутрипамятная генерация PBR-текстур (`THREE.CanvasTexture`)

Вместо вставки гигантских Base64-строк (которые раздувают HTML-файл до мегабайтов и могут вызвать сбой загрузки) все текстуры генерируются процедурно в памяти за 2 мс через HTML5 Canvas 2D API:

1. **Карта цвета (`cAlb`) и карта рельефа (`cBmp`, Bump Map)**:
   * На вертикальных линиях `U = 0.0, 0.25, 0.50, 0.75` рисуются глубокие темные канавки швов (`#161d14` на Albedo, `#202020` на Bump) и светлые полосы сбитой до металла краски на ребрах (`#9cb095`).
   * Вдоль нижней (`V ≈ 0.02..0.07`) и верхней (`V ≈ 0.93..0.98`) фасок рисуются чешуйчатые сварные швы (полукруглые наплывы сварки) и регулярные ряды шестигранных болтов с бликами.
   * В центре каждой из 4 граней (`X = 128, 384, 640, 896`) штампуются горизонтальные ребра жесткости и заводские военные трафареты (`MK-IV`, `ARMOR 46100`, `VENT // HOT`).
2. **Режим наложения**:
   * `wrapS = THREE.RepeatWrapping` (бесшовное замыкание по периметру детали).
   * `wrapT = THREE.ClampToEdgeWrapping`, `repeat.set(1.0, 1.0)` (строгое попадание нижней и верхней окантовки на нижнюю и верхнюю фаску каждой бронеплиты).

## 3. Иерархия Скелета и Компенсация Точек Вращения (Pivot Compensation)

Вся геометрия модели строится в удобных глобальных координатах (симметрично относительно центра `[0, 0, 0]`). Чтобы каждая деталь вращалась вокруг своего реального анатомического шарнира `(px, py, pz)`, используется двухслойный узел `createLocalPartGroup`:

```javascript
function createLocalPartGroup(name, pivotX, pivotY, pivotZ, parentGroup) {
  const joint = new THREE.Group();
  joint.name = name;
  joint.position.set(pivotX, pivotY, pivotZ); // Точка шарнира в пространстве родителя
  parentGroup.add(joint);

  const offsetGroup = new THREE.Group();
  offsetGroup.position.set(-pivotX, -pivotY, -pivotZ); // Компенсация глобальных координат меша
  joint.add(offsetGroup);
  return { joint, space: offsetGroup };
}
```

## 4. Аналитическая Инверсная Кинематика Ног (`solveLegIK` — Zero-Drift Foot Lock)

### Главный принцип
В прямой кинематике (FK) любое смещение или поворот таза (`pelvis`) приводит к тому, что стопы уходят под пол или скользят по воздуху. Чтобы робот обладал реальным весом в 15 тонн, **положение стоп задается в мировых координатах (`footTargetL`, `footTargetR`)**, а углы бедра, колена и голеностопа вычисляются аналитически в каждом кадре после установки позы таза.

### Пошаговый алгоритм `solveLegIK(side, targetWorldVec, footPitch, footYaw, footRoll)`

1. **Жесткая фиксация кости голени**:
   Координата лодыжки `ankleJoint.position` всегда жестко привязана к концу кости голени `[sx * 0.66, -1.72, 0.02]`. Стопа никогда не отрывается от ноги.
2. **Перевод мировой цели в локальное пространство таза**:
   Вызывается `rig.root.updateMatrixWorld(true)`, после чего мировая точка `targetWorldVec` переводится в систему координат `pelvis.children[0]` через `worldToLocal()`.
3. **Ограничение максимального вылета (Reach Clamping)**:
   Вычисляется вектор `(dx, dy, dz)` от тазобедренного шарнира `[sx * 0.54, -0.12, 0]` до цели. Если длина `D` превышает сумму длин бедра и голени `maxReach = LEG_L1 + LEG_L2 - 0.003` (`1.617 м`), вектор масштабируется до `maxReach`. Это гарантирует отсутствие ошибок `Math.acos(NaN)` при глубоких выпадах.
4. **Теорема косинусов для сгиба колена**:
   $$\cos(\beta) = \text{clamp}\left(\frac{L_1^2 + L_2^2 - D^2}{2 L_1 L_2}, -1, 1\right)$$
   Внутренний угол сгиба колена переводится в локальный угол вращения `kneeJoint.rotation.x = (Math.PI - Math.acos(cosB)) - REST_KNEE_OFFSET`.
5. **Точное наведение бедра кватернионом**:
   Вектор голени поворачивается на найденный угол колена `kx`, складывается с вектором бедра и дает вектор `_vHipToAnkleUnrot`. Затем `hipJoint.quaternion.setFromUnitVectors(_vHipToAnkleUnrot.normalize(), _vTargetLocal.normalize())` разворачивает бедро так, чтобы лодыжка попала точно в цель.
6. **Стабилизация подошвы параллельно полу**:
   Мировой кватернион колена инвертируется и умножается на целевой мировой кватернион стопы `(footPitch, footYaw, footRoll)`:
   `ankleJoint.quaternion.copy(_qParentWorld).invert().multiply(_qDesiredFoot)`. Подошва остается плоской на земле при любом наклоне корпуса!

## 5. Принципы Построения Полноценных Боевых и Локомоторных Анимаций

Чтобы анимация тяжелого меха выглядела мощно и физически достоверно, соблюдаются 4 закона биомеханики:

### Закон 1: Четырехфазная структура удара (`claw_smash`)
Любой силовой удар строится из 4 фаз внутри цикла `cycle in [0, 1]`:
* **Фаза 1 — Замах и шаг вперед (`0.00 .. 0.42`)**:
  Левая (передняя) нога делает широкий шаг вперед по параболе (`stepLift = Math.sin(stepU * Math.PI) * 0.28`) на `Z = +0.56` и с грохотом встает на опору. Таз смещается назад на опорную правую ногу и закручивается вправо (`-26°`), а корпус закручивается еще глубже (`-48°`, суммарно `-74°`). Голова (`sensorPod`) поворачивается в противофазу (`+85°`), удерживая прицел на враге. Правая рука с клешней уходит высоко за спину, пальцы раскрываются на 100%, а левая пушка выносится вперед как противовес.
* **Фаза 2 — Взрывной выпад и хлест кинематической цепи (`0.42 .. 0.58`)**:
  Обе стопы намертво прикованы к полу через IK. Таз резко бросает массу вперед (`+0.62 м` по Z) и вниз (`-0.27 м` по Y). Работает **хлест (Kinetic Whip)**: сначала раскручивается таз (`smoothstep(0.0, 0.85, u)`), затем корпус, и с нелинейным ускорением (`u^1.35`) по широкой внешней дуге (`Math.sin(armWhip * Math.PI)`) вылетает клешня со светящимся шлейфом.
* **Фаза 3 — Импульс удара, схлопывание и Hit-Stop (`0.58 .. 0.72`)**:
  В нижней точке удара клешня мгновенно захлопывается (`clawVal = 0.05`), высекая сноп искр и ударную волну. По всему корпусу проходит высокочастотная затухающая вибрация отдачи (`Math.sin(u * Math.PI * 10) * Math.exp(-u * 5)`), срабатывает тряска камеры.
* **Фаза 4 — Гидравлический возврат (`0.72 .. 1.00`)**:
  Плавный возврат центра тяжести и передней ноги в боевую стойку через `1.0 - smoothstep(0.0, 1.0, u)`.

### Закон 2: Многостадийные комбо-атаки (`all_out_attack`)
Сложные боевые сценарии разбиваются на последовательные таймслоты (например, цикл 10 секунд):
1. `0.00 - 0.24`: Сокрушительный удар клешней с выпадом и искрами.
2. `0.24 - 0.50`: Разворот корпуса левым плечом вперед, серия выстрелов из спаренного рельсотрона с жестким откатом стволов и отдачей в плечо.
3. `0.50 - 0.78`: Широкая опора, открытие крышек ракетных шахт на крыше, подъем пусковых контейнеров и поочередный залп самонаводящихся ракет по навесной траектории.
4. `0.78 - 1.00`: Активация гексагонального купола энергетического щита с пульсирующими волнами и охлаждение систем.

### Закон 3: Локомоция (Шаг и Бег) с переносом центра масс
* При ходьбе (`walk`) и беге (`run`) левая и правая ноги работают в противофазе (`phaseR = phaseL + Math.PI`).
* Стопа поднимается над землей только в полупериоде переноса (`Math.sin(phase) > 0`), а в опорной фазе жестко протягивается назад по полу (`Y = -1.72`).
* Таз смещается по горизонтали (`X`) в сторону опорной ноги и совершает вертикальные приседания на каждом шаге (на удвоенной частоте `2 * phase`), а руки работают в противофазе ногам для компенсации момента инерции.
